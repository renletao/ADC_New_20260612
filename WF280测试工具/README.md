# WF280 测试工具

**双击 `WF280测试工具.exe` 就能用**，不用装 Python、不用敲命令、不用命令行。

原「多功能小板测试」是编译好的 exe、没有源码，加不进 WF280 的新命令，
所以单独做了这个工具，专测 WF280 的全部功能，跟原工具并存、互不干扰。

## 第一次运行

1. 把 `WF280测试工具.exe` 拷到测试电脑任意位置（单独一个文件就行，不依赖其他文件）
2. 双击打开
3. 等 2~3 秒（单文件 exe 要先自解压，之后启动会快一些）

> 如果 Windows 提示「已保护你的电脑」，点「更多信息」→「仍要运行」。
> 这是未签名程序的常规提示，不是病毒。

## 使用流程

1. **选串口** → 插上板子后点「刷新」，选中对应的 COM 口（CH340 那类）
2. **点「连接」**（波特率和从机地址默认 115200 / 1，一般不用改）
3. 连上后顶部会显示 **「设备：固件 v1.0 · COM20 · 115200 8N1 · 从机 1」**
   —— 先看版本号对不对、是不是要测的那块板子
4. **填「设定电压」**（默认 3300 mV），然后点 **「▶ 开始全套测试」**

全套测试会自动按这个顺序跑，每一步都在表格里留记录：

| 步骤 | 内容 | 说明 |
| --- | --- | --- |
| ① | 设定电压 | 按你填的 mV 下发 `{1, 0x201}` |
| ② | 回读实际轨压 | `{1, 0x211}`，确认轨真的建立了 |
| ③ | 整机测试 | `cmd[0]=14`，这步的电压固件里固定 3300 mV |
| ④ | 读系数 | `{1, 0x209, 4}` |
| ⑤ | 读 M1 | `{1, 0x207, 4}` |
| ⑥ | OTP 校验 | `{11}` |
| ⑦ | 输出测试 | 设定 3300 走 `0x208`，设定 2000 走 `0x210` |
| ⑧ | 复测实际轨压 | 前面几项测完会断电，重新设压再读一次 |

最后一行是 **总判定 PASS / NG**，NG 的项在表格里标红。
只想测某一项时，用下面的「单项命令」。

> 注意：第 ③ 步整机测试的电压是固件里写死的 `WF280_TEST_RAIL_MV`（3300 mV），
> 上位机改不了。你填的电压影响的是 ① ② ⑦ ⑧ 这几步。

## 覆盖的命令

| 功能 | 命令 | 方式 | 返回 |
| --- | --- | --- | --- |
| 固件版本 | `{1, 0x104}` | 同步 | 主版本 / 次版本 |
| 整机测试 | `cmd[0] = 14` | 异步，走 `IsTaskDone` 队列 | 32 个寄存器：状态、轨压、电流、系数 |
| 轨压回读 | `{1, 0x211}` | 同步，随时可读 | 状态 + mV |
| OTP 校验 | `{11}` | 同步 | 1=通过 / 0xFF=失败 + 失败路号 |
| 输出测试 3.3 V | `{1, 0x208, 测量参数, 稳定时间}` | 同步 | 状态 + 6 个原始字节 |
| 输出测试 2.0 V | `{1, 0x210, 测量参数, 稳定时间}` | 同步 | 状态 + 6 个原始字节 |
| 读正常 bank 系数 | `{1, 0x209, 路数}` | 同步 | 状态 + N 路 16 位系数 |
| 读 M1 bank 系数 | `{1, 0x207, 路数}` | 同步 | 状态 + 待机/工作电流码 + N 路系数 |
| 设定 DAC 轨压（辅助） | `{1, 0x201, lo, hi}` | 同步 | 状态 |

命令码、结果偏移、判定阈值都对应固件 `Core/Src/wf280.c`、`Core/Inc/wf280.h`。
板子侧：USART2，**115200 8N1**，Modbus RTU 从机地址 **1**。

## 三个注意点

0. **先读版本再测**
   连上后第一件事是读 `{1, 0x104}`，正常返回 `v1.0`。
   如果读到 `0.0`，说明设备没应答或固件没烧进去，这时点测试只会拿到一堆 0。

1. **寄存器地址用 PDU 地址（0 基），不是 3xxxx/4xxxx 引用号**
   实测这块板子：**写命令 40000、读结果 30000**。
   发 40001 / 30001 会直接被固件回异常码 02（非法寄存器地址）。
   固件注释里写的「30001 起」「40001」是 Modbus 引用号写法，上线要减 1。
   工具连接时会自动试 40000/30000 和 40001/30001 两套，日志里会打印最终用的是哪套。

2. **轨压读到的是实测值，不是设定值**
   `0x211` 走 PB1/ADC1_IN9 分压回采，读到的是 DUT 真实轨压。
   「设了 3300 却读到 1200」说明轨没起来，不是命令没生效。
   如果上一条命令刚把轨关掉，单独点「读取轨压」会读到接近 0 mV，这是对的。

## 关于电流值（为什么固件报 0）

`ADS1220` 是 24 位有符号 ADC，这块板子的电流通道读出来是**负值**，
比如工作电流原始码 `0xFFFD29AE`，其实是 24 位补码 `0xFD29AE` = **-185938**，
被固件符号扩展成 32 位后 bit31 变成 1，而固件里有这么一行：

```c
if (!rail_mv || (raw & 0x80000000)) return 0;   // 把负值当成无效数据
```

于是工作电流一律返回 `0 uA`。按固件自己的公式（满量程 8388608、分流 120 Ω、
轨压 3.3 V），这个原始码对应：

```
185938 × 3296 × 1000 / (8388608 × 120) ≈ 609 uA
```

也就是分流电阻上 73 mV 的压降，是个正常的读数，只是方向为负。

所以工具里加了一列 **「工作电流（推算）」**：按同一套常数把原始码取绝对值重算一遍，
不受固件那行判断影响。原始码本身也一并显示，方便对账。

要彻底修好有两种方式：

1. **改硬件**：把电流检测的分流电阻两端（或 ADC 差分输入极性）对调，
   读出来就是正值，固件不用改。
2. **改固件**：把 `wf280_current_ua()` 里的有效性判断改成按 24 位有符号解释并取绝对值，
   例如：

```c
int32_t v = (int32_t)raw;
if (v & 0x00800000) v |= 0xFF000000;   /* 24 位符号扩展 */
if (v < 0) v = -v;                     /* 取绝对值 */
```

> 休眠电流同样按这个方式算。静止时原始码只有几十个 LSB，
> 换算出来不到 0.1 uA，看起来偏小，可以用万用表对比确认是否需要校准零点和增益。

## 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 连接后显示「通讯失败」 | 串口口选错，或板子没上电；换个 COM 口再试 |
| 提示异常码 02 | 寄存器基址不对（固件可能换了约定），看日志里自动识别到哪套 |
| 输出测试报「NOR 忙等超时」 | 稳定时间太短。默认 300 ms，冷启动时可以加到 500~800 ms |
| 整机测试一直等到超时 | 检查 DUT 是否插好；默认超时已给到 120 s |
| 打不开串口（拒绝访问） | 原「多功能小板测试」还开着，先把它的串口断开或关掉窗口 |

## 源码与重新打包

界面和协议是 Python 写的，已打包进 exe，**日常使用完全不需要 Python**。
只有要改功能时才需要动源码：

```
src/
  wf280_tool.py    入口（图形界面 / 命令行）
  gui.py           tkinter 界面
  wf280_proto.py   命令封装与结果解码
  mb_rtu.py        极简 Modbus RTU 主站（不依赖 pymodbus）
  selftest.py      离线自检
build.bat          一键重新打包
```

重新打包：装 Python 3.8+（官方版，自带 tkinter）和 `pip install pyserial pyinstaller`，
然后双击 `build.bat`，根目录会生成新的 exe。

离线自检（不需要板子，用假从机验证协议，14 项）：

```
python src/selftest.py
```

命令行用法（需要源码环境）：

```
python src/wf280_tool.py --port COM5 version
python src/wf280_tool.py --port COM5 full
python src/wf280_tool.py --port COM5 rail
```

退出码：`0` 通过、`1` NG、`2` 通讯错误，方便产线脚本判断。
